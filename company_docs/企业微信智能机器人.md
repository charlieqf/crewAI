## 1. 调研结论

### ✅ 强烈建议改用"智能机器人"

智能机器人**满足核心需求**：在群聊中 @机器人，机器人以自己的身份直接回复。

> [!WARNING]
> **群ID不确定性**：智能机器人回调 payload 中的群/聊天 ID 字段名称尚未验证。
> 当前代码尝试多种字段名（`chat_id`, `chatid`, `roomid` 等），需通过实际回调日志确认。
> 若无稳定群 ID，多群上下文隔离可能受影响。部署后需验证此项。

### 当前架构 vs 智能机器人架构

| 特性 | 当前架构（自建应用+群Webhook） | 智能机器人架构 |
| :--- | :--- | :--- |
| **群聊 @机器人** | ❌ 不支持（Webhook只能发不能收） | ✅ 原生支持 |
| **机器人身份回复** | ⚠️ 需要通过Webhook发送 | ✅ 直接以机器人身份回复 |
| **流式回复** | ❌ 不支持 | ✅ 支持（最长6分钟） |
| **多机器人** | 需要1个应用+3个Webhook | ✅ 可创建3个独立智能机器人 |
| **加密方式** | XML 加密 | **JSON 加密**（更简单） |
| **receiveid** | 需要设置 corpid | **空字符串**（更简单） |

## 2. 智能机器人核心能力

### 2.1 使用场景

| 场景 | 描述 | 示例 |
| :--- | :--- | :--- |
| **群聊问答** | 在群里 @机器人 提问，机器人直接回复 | `@gemini 今天天气怎么样？` |
| **文档分析** | 发送文件给机器人，机器人分析内容 | 发送 PDF + `@gemini 总结这份报告` |
| **代码助手** | 询问代码问题或请求代码生成 | `@chatgpt 写一个 Python 排序函数` |
| **翻译助手** | 多语言翻译 | `@grok 把这段翻译成英文` |
| **创意写作** | 文章、邮件、文案生成 | `@gemini 帮我写一封感谢信` |

### 2.2 聊天方式

#### 群聊中 @机器人（主要方式）
```
用户A: @gemini 帮我解释一下量子计算
gemini: 量子计算是一种利用量子力学原理进行计算的技术...

用户B: @chatgpt 上面的解释太复杂了，能简单点吗？
chatgpt: 简单来说，量子计算就像是...
```

#### 引用消息回复
```
用户: [引用某条消息] @gemini 这个观点对吗？
gemini: 关于引用的消息，我的看法是...
```

#### 多轮对话（基于上下文）
```
用户: @gemini Python 和 Java 哪个更适合初学者？
gemini: 对于初学者，我推荐 Python，因为...

用户: @gemini 那学 Python 需要多久？
gemini: 基于我们刚才讨论的 Python 学习路径...
       （机器人记住了上下文）
```

### 2.3 消息类型支持

| 消息类型 | 接收 | 回复 | 说明 |
| :--- | :---: | :---: | :--- |
| **文本** | ✅ | ✅ | 最常用，支持流式回复 |
| **图片** | ✅ | ✅ | 可接收图片并分析（需 Vision 模型） |
| **语音** | ✅ | ❌ | 可接收语音（需转文字处理） |
| **文件** | ✅ | ✅ | PDF/Word/Excel 等，需下载后处理 |
| **引用消息** | ✅ | - | 可获取被引用的原始消息内容 |
| **图文混排** | ✅ | ✅ | 图片+文字组合消息 |
| **Markdown** | - | ✅ | 回复支持 Markdown 格式 |

### 2.4 文件处理流程

#### 接收文件
```
1. 用户发送文件 + @gemini 分析这个文件
2. 服务器收到回调，包含 media_id
3. 使用 media_id 调用企微 API 下载文件
4. 解析文件内容（PDF/Word/Excel）
5. 将内容发送给 LLM 处理
6. 返回分析结果
```

#### 文件消息 JSON 结构
```json
{
  "msgtype": "file",
  "file": {
    "media_id": "xxx",           // 用于下载文件
    "file_name": "报告.pdf",      // 文件名
    "file_size": 102400          // 文件大小(字节)
  },
  "from": {
    "user_id": "zhangsan",
    "name": "张三"
  }
}
```

> [!NOTE]
> **字段名待验证**：上述 JSON 结构基于官方demo和常见实践推测。
> 实际智能机器人回调可能使用不同字段名（如 `mediaId`, `fileName` 等）。
> 部署后需通过日志确认实际 payload 结构。

#### 优先级建议

1. **高优先级**（核心体验）
   - 引用消息处理：提取被引用内容作为上下文
   
2. **中优先级**（增强功能）
   - 图片消息：需要 Gemini Vision / GPT-4V
   - 文件消息：需要企微下载 API + 文档解析

3. **低优先级**（可选）
   - 语音消息：需要语音转文字服务

### 2.5 流式回复机制

智能机器人支持**最长 6 分钟**的流式回复，非常适合 LLM 场景。

#### 工作原理
```
[T+0s]   用户: @gemini 写一篇关于 AI 的文章
[T+0.5s] 服务器: 收到消息，立即返回 {"finish": false, "content": "思考中..."}
[T+1s]   企微客户端: 显示 "思考中..."
[T+2s]   企微: 发送刷新请求 (msgtype=stream)
[T+2s]   服务器: 返回 {"finish": false, "content": "好的，我来写一篇..."}
[T+3s]   企微客户端: 更新显示内容
...（重复刷新，每次显示最新内容）...
[T+30s]  服务器: LLM 完成，返回 {"finish": true, "content": "完整的文章内容..."}
[T+30s]  企微客户端: 显示最终完整回复
```

#### 超时处理
- **6分钟内**：企微会持续刷新获取最新内容
- **超过6分钟**：企微停止刷新，显示最后获取的内容

> [!IMPORTANT]
> **主动推送待实现**：对于可能超时的复杂任务，理想方案是完成后主动推送通知。
> 但智能机器人的主动推送需要单独的 API 凭据和集成，目前尚未实现。
> 当前建议：在6分钟内尽量完成响应。

### 2.6 与自建应用的对比

| 功能 | 自建应用 | 智能机器人 |
| :--- | :--- | :--- |
| 群聊 @回复 | ❌ 不支持 | ✅ 原生支持 |
| 机器人身份 | ⚠️ 通过 Webhook | ✅ 直接以机器人身份 |
| 流式回复 | ❌ 不支持 | ✅ 支持（6分钟） |
| 私聊 | ✅ 支持 | ⚠️ 需单独配置 |
| 主动推送 | ✅ 支持 | ✅ 支持 |
| 审批/打卡等 | ✅ 丰富 API | ❌ 不支持 |

**结论**：智能机器人专为**群聊 AI 对话**设计，自建应用适合**企业系统集成**。

## 3. 官方示例代码分析

参考 `company_docs/aibot_demo_python3/`

### 3.1 回调端点
```python
# URL 验证
@app.get("/ai-bot/callback/demo/{botid}")
async def verify_url(...)

# 消息处理
@app.post("/ai-bot/callback/demo/{botid}")
async def handle_message(...)
```

### 3.2 JSON 加密（不是 XML）
```python
# receiveid 是空字符串（比自建应用简单）
receiveid = ''
wxcpt = WXBizJsonMsgCrypt(os.getenv('Token', ''), os.getenv('EncodingAESKey', ''), receiveid)
```

### 3.3 流式消息格式
```python
def MakeTextStream(stream_id, content, finish):
    return {
        "msgtype": "stream",
        "stream": {
            "id": stream_id,      # 任务ID
            "finish": finish,     # 是否完成
            "content": content    # 当前内容
        }
    }
```

### 3.4 消息处理流程
1. 收到 `text` 消息 → 调用 LLM → 返回首次流式回复
2. 收到 `stream` 消息（刷新请求）→ 返回最新内容 → 直到 `finish=True`
