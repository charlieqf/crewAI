# 单元测试与质量保证指南 (开发团队专用)

为了确保 CrewAI 项目的高质量交付，本项目强制执行 **测试驱动开发 (TDD)**。本指南说明了如何运行测试以及测试的标准。

---

## 1. 环境准备

本项使用 `uv` 进行环境管理。在开始测试前，请确保您的环境已同步：

```powershell
# 同步环境（自动创建虚拟环境并安装依赖）
uv sync
```

---

## 2. 运行测试命令

### 2.1 运行所有测试
在项目根目录下执行：
```powershell
uv run python -m unittest discover tests
```

### 2.2 运行特定工具的测试 (如 WeComTool)
```powershell
$env:PYTHONPATH="."; uv run python -m unittest tests/tools/test_wecom_tool.py
```

---

## 3. 测试应达到的目标效果

### 3.1 预期的执行结果 (OK)
一个成功的测试运行应该在控制台输出类似以下的内容：
```text
..
----------------------------------------------------------------------
Ran 2 tests in 0.019s

OK
```
- **`.`**: 表示一个测试用例通过。
- **`OK`**: 表示所有用例均通过。

### 3.2 失败的信号 (FAILED / ERROR)
如果看到 `F` (断言失败) 或 `E` (运行时错误)，开发者必须在提交代码前修复：
- **`F` (Failure)**: 逻辑返回的结果与预期不符（例如：API 报错了但你没处理）。
- **`E` (Error)**: 代码语法错误、导入缺失或未处理的异常。

---

## 4. 开发红线与原则

1. **红灯进场 (TDD)**：新功能开发前必须先写测试用例。看到测试失败（红灯）后，再编写实现逻辑使之变绿。
2. **禁止真实网络调用**：单元测试中**严禁**向企业微信、GitLab 等正式接口发起真实请求。必须使用 `unittest.mock` 模拟外部 HTTP 响应。
3. **Pydantic 强制校验**：所有自定义工具（Tools）的输入必须通过 `args_schema` 进行校验，并在测试中验证非法输入的拦截情况。
4. **回归检查**：修改旧代码后，必须确保 `tests/` 下的所有历史用例依然为 `OK`。

---

## 5. 常见问题排查 (Troubleshooting)

- **ModuleNotFoundError**: 确保使用了 `uv run` 或已激活 `.venv` 虚拟环境。
- **ImportError**: 检查 `PYTHONPATH` 是否包含项目根目录。
- **Mock失效**: 确认 `@patch` 的路径是代码**被调用时**的路径，而非定义路径。

> [!TIP]
> 稳定的单元测试是我们在复杂的多 Agent 协作中不掉链子的唯一保证。
