# CrewAI + 企业微信 (WeCom) 深度集成方案

本方案旨在让 CrewAI 成为您公司企业微信群中的“智能秘书”和“首席分析师”，实现信息的实时响应与深度的价值提炼。

---

## 1. 实时参与群聊讨论

### 需求澄清（已确认 ✅）

**1. Agent 参与的讨论类型**

| 讨论类型 | 示例 | 需要 Agent | 知识来源 |
| :--- | :--- | :---: | :--- |
| **代码相关问题** | "这个函数是干什么的？" | ✅ | GitLab 代码库 |
| **项目进度查询** | "这个 Issue 进展如何？" | ✅ | GitLab Issue/MR |
| **技术文档查阅** | "我们的 API 文档在哪？" | ✅ | 内部文档库 |
| **历史讨论回顾** | "上周我们讨论过这个问题" | ✅ | 群聊天记录 |
| **通用问答** | "Python 怎么读取 JSON？" | ✅ | LLM 通用知识 |

**2. 知识库来源**

| 知识来源 | 是否接入 | 技术方案 |
| :--- | :---: | :--- |
| **GitLab 代码库** | ✅ | OpenHands（file_editor, grep） |
| **GitLab Commit Messages** | ✅ | GitLabTool API（新增） |
| **GitLab Issue/MR** | ✅ | GitLabTool API |
| **群聊天记录** | ✅ | SQLite/Redis 存储 + RAG |
| **内部文档** | ✅ | RAG 向量索引 |

**3. 深度代码理解**

| 场景 | 示例 | 框架 |
| :--- | :--- | :--- |
| 简单代码查询 | "给我看 User 类的定义" | GitLabTool |
| 复杂代码分析 | "这个 Bug 可能在哪里？" | OpenHands ✅ |

---

### 实现原理与工作机制
通过 **WeCom Webhook 回调** 与 **FastAPI 消息代理** 构建。
1.  **消息监听**：用户在群里 `@AI` 或发送特定指令时，企业微信服务器将加密的 XML 消息推送到您的 FastAPI 回调地址。
2.  **解密与分发**：中台服务解密消息并识别用户意图，如果需要 AI 介入，则调用 CrewAI。
3.  **多智能体响应**：
    -   **Dispatcher Agent**：负责解析用户具体在问什么（是查代码、查进度还是查资料）。
    -   **Executor Agent**：根据指令调用 `GitLabTool` 或 `SearchTool` 获取答案。
    -   **（可选）OpenHands**：如涉及复杂代码分析，转交 OpenHands 执行。
4.  **回复发送**：通过**群聊机器人 Webhook URL** 将回复推送回群组（非应用 API）。

### 框架现状（CrewAI 现在有什么？）
-   **`ZapierActionTools`**：虽然支持 Zapier 间接连接微信，但为了国内稳定性，我们更推荐自定义工具。
-   **长短期记忆 (Memory)**：能记住同一个群聊 Session 之前的对话上下文，确保对话连贯。
-   **多 Agent 协作**：支持一个 Agent 去查资料，另一个 Agent 进行润色后再由机器人发出。

## 2. 每日对话汇总与分析

### 实现原理与工作机制
这是一个基于 **时间驱动 (Cron)** 的 **全量数据摘要流程**。
1.  **静默采集**：中台将全天的群聊记录实时暂存至 SQLite 或 Redis 数据库。
2.  **定时唤醒**：每晚 22:00，Flow 任务被触发。
3.  **复盘与生成**：
    -   **Collector Agent**：从数据库读取当日所有对话。
    -   **Analyst Agent**：对内容进行聚类分析，区分出“技术决策”、“商务机会”、“紧急 Bug”三类。
    -   **Coordinator Agent**：根据分析结果生成次日的《团队重点跟进事项列表》。
4.  **推送报告**：将结构化 Markdown 报告发送给管理员。

### 框架现状（CrewAI 现在有什么？）
-   **完备的 Flows 框架**：非常适合这种从“读取数据库”到“多 Agent 处理”再到“结果推送”的复杂长流程。
-   **JSON 强制输出**：可以让 AI 强制输出 JSON 格式的待办事项，方便集成到您公司的其他看板系统。

## 3. 定制开发需求（您需要做什么？）

### 基础设施开发
1.  ** WeCom 回调中间件**：
    -   实现企业微信特有的 `AES 消息加解密` 和 `Base64 编码` 逻辑（已有现成的 Python SDK）。
    -   开发一个简单的群聊消息存储中间件。
2.  ** `WeComTool` 开发**：
    -   实现 `send_text_message()` 和 `send_markdown_message()` 两个核心 API。

### 业务逻辑定制
1.  **群组白名单机制**：防止 AI 误入非相关群聊，按需开启。
2.  **角色定义 (Backstory)**：为您公司的 5 个团队定制 5 套不同的回复风格，例如“运维保障组”的 AI 风格更严谨，“前端设计组”的 AI 风格更具创意。

---

## 🎯 总结：技术价值与投入
-   **技术价值**：将企业微信从简单的“聊天软件”升级为集成了公司内部库和 AI 智力的“智能中枢”。
-   **首期开发量**：
    -   **基础连通 (Webhook)**：3-4 天（侧重于安全校验和消息吞吐）。
    -   **每日复盘逻辑**：3-5 天（侧重于摘要算法的准确度和分类逻辑）。

> [!IMPORTANT]
> 此方案的运行需要一台具有公网 IP（或通过内网穿透）的服务器，用于接收企业微信的 HTTPS 回调信号。
