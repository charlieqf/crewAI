# 企业 AI 自动化集成项目：需求定义与开发计划 (PRD)

本文档整合了公司关于 CrewAI 与内部系统（GitLab、企业微信）及创新业务（机器人、数字人）的集成需求与落地规划。

---

## 1. 项目背景与目标
针对小型软件公司，利用 CrewAI 的多智能体协作能力，实现开发流程自动化、业务决策智能化以及沟通中枢 AI 化。

---

## 2. 核心需求定义

### 2.1 软件开发自动化 (GitLab Integration)
- **需求描述**：自动执行每笔 Commit 的代码评审，通过群聊/邮件通知结果。建立跨团队（5 个组）的多 AI 协同讨论室。
- **关键特性**：
    - 自动化抓取代码 Diff。
    - 专家级代码逻辑与安全审计。
    - 讨论室集成项目全量代码知识库 (RAG)。

### 2.2 创新业务支持 (Robotics & Digital Humans)
- **需求描述**：支持学校/博物馆机器人场景调研；自动化数字人直播脚本与视觉素材创作。
- **关键特性**：
    - 全球机器人案例情报监控。
    - 社交平台热点趋势捕捉与直播文案生成。
    - AI 辅助机器人交互预案设计。

### 2.3 企业沟通中枢 (WeCom Integration)
- **需求描述**：AI 接入企业微信群，参与实时技术讨论，并每日生成协作复盘报告。
- **关键特性**：
    - Webhook 消息实时解密与响应。
    - 任务看板与待办事项自动提炼。

## 3. 核心组件深度解析：WeComTool

### 3.1 什么是 WeComTool？
`WeComTool` 是项目中的 **消息发送组件**（AI 的“嘴巴”）。在技术实现上，它是一个继承了 `crewai.tools.BaseTool` 的 Python 类。它的职责是将 **CrewAI Agent 的决策输出** 发送到 **企业微信**。

### 3.2 两种工作模式（重要）
根据业务场景的不同，WeComTool 涉及两套完全不同的底层机制：

| 模式 | 技术形态 | 执行逻辑 | 对应需求场景 |
| :--- | :--- | :--- | :--- |
| **主动推送 (Outgoing)** | **HTTP Client (REST API)** | Agent 调用工具 -> WeComTool 向企业微信发送 `POST` 请求（带 Secret 置换的 Token）。 | 代码评审通知、每日复盘报告推送、行业热点预警。 |
| **被动接收 (Incoming)** | **Webhook 回调 (Callback)** | 外部事件（用户在群里发消息） -> 触发企业微信回调您的 FastAPI 中台 -> **WeCom Callback Server** 解析 XML 负载并路由给 Agent。 | AI 参与群聊互动、接收用户指令。 |

### 3.3 核心内部逻辑
- **Token 托管**：WeCom 的 `access_token` 每 2 小时过期一次。`WeComTool` 内部维护一个缓存机制，当 Token 失效时自动根据 `corp_id` 和 `secret` 进行无感重刷。
- **消息格式适配**：
    - **文字消息**：用于日常简短交流。
    - **Markdown 消息**：用于展示复杂的 **Code Review 差分**、表格样式的**热点汇总**。
    - **图文消息**：用于展示创新业务中生成的机器人设计图或数字人素材。

### 3.4 模块间的“发布-订阅”关系
`WeComTool` 并不是被某个 Agent 锁死的，而是作为一种“能力”按需分配：

1. **研发侧同步**：`GitLabAgent` 完成审计 -> 获取审计结论 -> 调用 `WeComTool._run(msg_type="markdown")`。
2. **业务侧汇总**：`TrendAgent` 搜集到热点 -> 整理为摘要 -> 调用 `WeComTool._run(msg_type="text")`。
3. **管理侧提醒**：`ReviewAgent` 总结出待办 -> 生成 Checkbox 列表 -> 调用 `WeComTool._run(msg_type="markdown")`。

> [!NOTE]
> 简而言之，`WeComTool` 是 AI 的“嘴巴”（发送消息），`WeCom Callback Server` 是 AI 的“耳朵”（接收消息）。

## 4. 架构与部署环境建议

基于项目需求（长时运行、Webhooks 接收、私密性），我们推荐以下部署架构：

### 4.1 最佳决策：Docker 容器 + Linux VM
- **建议原因**：
    - **Docker**：确保 CrewAI 复杂的 python 依赖环境在开发、测试、生产环境中完全一致。
    - **Linux VM**：提供固定公网 IP（WeCom 必要条件），且适合 AI 这种可能持续数分钟的“深度思考”长任务。
- **推荐平台**：阿里云 ECS 或 Google Cloud (GCP) Compute Engine。

### 4.2 云平台深度对比：阿里云 vs 腾讯云

针对您的业务场景，这两个平台的差异点如下：

| 维度 | 阿里云 (Alibaba Cloud) | 腾讯云 (Tencent Cloud) |
| :--- | :--- | :--- |
| **企业微信集成** | 兼容性良好，需标准 API 对接。 | **主场优势**。作为腾讯自家产品，网络抖动更小，且有更多官方集成插件。 |
| **AI 基础设施** | **更强**。ModelScope 社区和 PA-AI 平台在模型推理速度上略占优势。 | **更贴近业务**。在音视频、数字人生成算法上有深厚积累。 |
| **开发者体验** | 偏向于通用云基础设施，稳定度高。 | 偏向于互联网生态，对社交、内容创作更友好。 |
| **结论建议** | 适合追求**底层 AI 能力极致稳定**的场景。 | **更推荐**。考虑到您的核心需求包含“企业微信集成”和“数字人”，腾讯云的生态契合度更高。 |

### 4.3 硬件规格建议
- **规格**：2 核 8G（CrewAI 在多 Agent 运行时对内存有一定要求）。
- **网络**：必须具备固定公网 IP，开放 80/443/8000 端口。

## 6. 准入前提与资源准备
1. **企业微信应用**：需申请自建应用并开启“接收消息”权限。
2. **GitLab Token**：需具备全库读取及评论发表权限。
3. **LLM API**：建议配置 OpenAI (GPT-4) 和 Google Gemini 的双 API 混合调用。
4. **服务器资源**：腾讯云 CVM 或阿里云 ECS 实例，需固定公网 IP 并完成安全组 80/443/8000 端口映射。
