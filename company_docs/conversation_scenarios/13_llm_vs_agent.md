# 区分 LLM 对话与 Agent 任务

## 核心区别

| 维度 | **LLM 对话 (Chat)** | **Agent 任务 (Task)** |
|-----|-------------------|---------------------|
| **本质** | **响应式**：一问一答，基于上下文生成回复 | **目标导向**：为达成目标，自动规划和执行一系列步骤 |
| **执行流** | 线性：用户输入 -> LLM 处理 -> 回复 | 循环/复杂：思考 -> *调用工具* -> *观察结果* -> 再思考 -> 回复 |
| **耗时** | 短（秒级） | 长（可能数十秒到几分钟） |
| **副作用** | 无（仅生成文本/文件） | 有（可能修改代码、提交 PR、查询数据库、发送通知） |
| **能力边界** | 受限于上下文窗口和预训练知识 | 可通过工具扩展无限能力（联网、查库、执行代码） |

## 场景分类矩阵

### 1. 纯 LLM 对话 (Direct Chat)
*机制：直接调用 LLM API，仅依赖 Context Window*

- **基础对话**: "Python 里的 yield 是什么？"
- **自定义角色**: "你是一个产品经理..." (/set_prompt)
- **文件与图片分析**: "总结这个这个 PDF" (Gemini 1.5 原生支持多模态，无需 Agent)
- **文件生成**: "/file-html 做个页面" (虽生成了文件，但主要还是基于 Prompt 的一次性生成)
- **迭代改进**: "重做一版" (基于历史对话的生成)

### 2. 增强型 LLM 对话 (RAG/Tool-assisted Chat)
*机制：LLM + 检索/简单工具，仍保持对话形态*

- **代码库问答 (/codebase)**:
    - *虽涉及检索，但本质是 RAG 增强的对话*
    - 检测上下文 -> 检索相关代码片段 -> 注入 Context -> LLM 回答
- **历史回溯**:
    - "上周五说了什么？" -> 检索 Archive DB -> 总结回答
- **引用回复**:
    - 引用文件/消息 -> 获取引用内容 -> 注入 Context -> 回复

### 3. CrewAI Agent 任务 (Autonomous Agents)
*机制：CrewAI 框架，多 Agent 协作，规划-执行循环*

- **代码审查 (Code Review)**:
    - *触发*: 收到 GitLab Commit URL
    - *Agent*: `CodeReviewer`, `SecurityAuditor`, `TechLead`
    - *流程*: 获取 Diff -> 静态分析 -> 安全扫描 -> 综合评分 -> 生成报告
    - *特征*: 多步骤，甚至可能评论 GitLab PR

- **复杂 Bug 修复**:
    - *触发*: "/fix_bug [截图]"
    - *Agent*: `Debugger`, `Researcher`, `Coder`
    - *流程*: 分析截图 -> 检索代码 -> 复现问题(可选) -> 生成修复方案 -> 验证
    - *特征*: 需要推理链 (Chain of Thought)

- **周报自动生成**:
    - *触发*: 定时任务
    - *Agent*: `Summarizer`
    - *流程*: 扫描全量 Archive -> 分类话题 -> 提取关键决策 -> 格式化输出

- **项目脚手架生成**:
    - *触发*: "/new_project [需求文档]"
    - *Agent*: `Architect`, `Scaffolder`
    - *流程*: 分析需求 -> 规划目录结构 -> 生成多个文件 -> 创建 Git 仓库
    - *特征*: 产生大量副作用 (文件/仓库)

## 架构映射

### 路径 A：FastAPI -> `_call_llm_async`
**(用于 LLM 对话 & 增强对话)**
- **轻量级**
- 直接流式返回
- 使用 `ChatContextManager`

### 路径 B：FastAPI -> `CrewAI Flow` / `Agent`
**(用于 Agent 任务)**
- **重量级**
- 可能异步执行 (Background Task)
- 使用 `Kickoff`
- 结果可能通过回调通知

## 决策指南：何时用 Agent？

1. **需要多步推理吗？** (例如：先查 A，根据 A 的结果决定查 B 还是查 C) -> **Agent**
2. **需要使用外部写工具吗？** (提交代码、发邮件) -> **Agent**
3. **需要多角色视角吗？** (既要安全审计，又要性能评估) -> **CrewAI**
4. **单次 LLM 调用无法完成吗？** (超过 Token 限制，需要拆解任务) -> **Agent**

如果只是"根据上下文回答问题"或"根据指令生成文本格式"，**保留在 LLM 对话层**通常响应更快、体验更好。
